SYN flood network attack analysis

Reading a Wireshark log to find out why a website timed out, and explaining how a SYN flood exhausts a server.

  • Network traffic analysis
  • TCP handshake
  • DoS vs DDoS
Download as PDF

Section 1Identify the type of attack that may have caused this network interruption

One potential explanation for the website's connection timeout error message is: a denial of service (DoS) attack, most likely a SYN flood.

The logs show that: one IP address, 203.0.113.0, keeps sending SYN requests to the web server (192.0.2.1) and never finishes the handshake. Entries 52 to 83 show it sending SYN packets again and again, while normal visitors from the 198.51.100.x range first connect without trouble and then start to get reset (RST, ACK) or stay without an answer. In the last entry the server replies with a 504 Gateway Time-out.

This event could be: a direct DoS SYN flood, because all the malicious packets come from one single source address. If they came from many addresses it would be a distributed attack (DDoS).

Section 2Explain how the attack is causing the website to malfunction

When website visitors try to establish a connection with the web server, a three-way handshake occurs using the TCP protocol. Explain the three steps of the handshake:

  1. The visitor's computer sends a SYN packet to the web server to ask for a connection.
  2. The server answers with a SYN, ACK packet to accept the request, and it keeps some resources reserved for that connection.
  3. The visitor's computer sends a final ACK packet. The connection is now open and the page can be requested.

Explain what happens when a malicious actor sends a large number of SYN packets all at once:

The attacker sends so many SYN packets in a short time that the server tries to answer every one of them with a SYN, ACK. For each of them it reserves memory and waits for an ACK that never comes. These half-open connections pile up until the server has no resources left, and it can't accept new visitors anymore.

Explain what the logs indicate and how that affects the server:

In the log the address 203.0.113.0 repeats the SYN request dozens of times, at an abnormal speed. In the beginning the server still manages to serve real employees (for example 198.51.100.14 loads sales.html), but later the connections from other employees such as 198.51.100.5 and 198.51.100.16 are reset or time out. Finally the server answers with 504 Gateway Time-out. The result is that employees can't open the website, and the service is down until the traffic stops. As a first step I would block 203.0.113.0 on the firewall and turn on SYN cookies or rate limiting on the server.
