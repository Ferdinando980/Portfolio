File permissions in Linux

Checking and tightening permissions on files, a hidden file and a directory with ls and chmod.

  • Linux command line
  • ls
  • chmod
  • least privilege
Download as PDF

Project description

The research team in my organization asked me to update the permissions of some files and directories in the projects directory. The permissions in place did not match the level of access each person should have, and fixing them keeps the system more secure. I did it in four steps: check the current permissions, then change them on a normal file, on a hidden file and on a directory.

Check file and directory details

I listed the content of the projects directory with ls -la. The -l option gives the long format, with permissions, owner and group, and -a also shows hidden files:

cd /home/researcher2/projects
ls -la

The directory holds a subdirectory called drafts, a hidden file called .project_x.txt and five regular project files. The first column of every line is a string of 10 characters that describes the permissions.

Describe the permissions string

The 10 characters are read in groups. The 1st character is the file type: d for a directory, a hyphen for a regular file. Characters 2 to 4 are the permissions of the user (the owner), 5 to 7 are for the group, and 8 to 10 are for other, which means everyone else on the system. In each group, r is read, w is write and x is execute, and a hyphen means that permission is not given.

For example, project_t.txt has -rw-rw-r--. It starts with a hyphen, so it is a regular file. The user and the group can read and write it, other can only read it, and nobody can execute it.

Change file permissions

The organization decided that other should not have write access to any file. In the listing, project_k.txt was the file where other could still write, so I removed that permission and checked the result:

chmod o-w project_k.txt
ls -la

Change file permissions on a hidden file

The team archived project_x.txt. Nobody should be able to write to it, but the user and the group must be able to read it. The file name starts with a dot, which is why it is hidden and only appears with ls -a. I removed write permission from the user and the group, and added read permission for the group:

chmod u-w .project_x.txt
chmod g-w .project_x.txt
chmod g+r .project_x.txt
ls -la

Change directory permissions

Only researcher2 may have access to the drafts directory and what is inside it. For a directory, the execute permission is what allows a user to enter it. The group still had it, so I removed it. The user researcher2 already had execute, so nothing had to be added:

chmod g-x drafts
ls -la

Summary

I changed the permissions so they follow the access rules of the organization. I first used ls -la to see the situation, and that is what told me which changes were needed. Then I used chmod three times, with the symbolic mode, on a regular file, on a hidden file and on a directory, and checked each time with ls -la.
