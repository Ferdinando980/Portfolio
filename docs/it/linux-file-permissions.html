Permessi dei file in Linux

Controllo e restrizione dei permessi di file, di un file nascosto e di una directory con ls e chmod.

  • ls
  • chmod
  • privilegio minimo

Descrizione del progetto

Il team di ricerca della mia organizzazione mi ha chiesto di aggiornare i permessi di alcuni file e directory nella directory projects. I permessi presenti non corrispondevano al livello di accesso che ogni persona dovrebbe avere, e sistemarli rende il sistema più sicuro. L'ho fatto in quattro passaggi: controllare i permessi attuali, poi cambiarli su un file normale, su un file nascosto e su una directory.

Controllare i dettagli di file e directory

Ho elencato il contenuto della directory projects con ls -la. L'opzione -l dà il formato lungo, con permessi, proprietario e gruppo, mentre -a mostra anche i file nascosti:

cd /home/researcher2/projects
ls -la

La directory contiene una sottodirectory chiamata drafts, un file nascosto chiamato .project_x.txt e cinque file di progetto normali. La prima colonna di ogni riga è una stringa di 10 caratteri che descrive i permessi.

Descrivere la stringa dei permessi

I 10 caratteri si leggono a gruppi. Il 1° carattere è il tipo di file: d per una directory, un trattino per un file normale. I caratteri da 2 a 4 sono i permessi dell'utente (il proprietario), da 5 a 7 quelli del gruppo e da 8 a 10 quelli di other, cioè tutti gli altri utenti del sistema. In ogni gruppo r è lettura, w è scrittura e x è esecuzione, e un trattino significa che quel permesso non è concesso.

Per esempio, project_t.txt ha -rw-rw-r--. Comincia con un trattino, quindi è un file normale. L'utente e il gruppo possono leggerlo e scriverlo, other può solo leggerlo e nessuno può eseguirlo.

Cambiare i permessi di un file

L'organizzazione ha deciso che other non deve avere accesso in scrittura a nessun file. Nell'elenco, project_k.txt era il file in cui other poteva ancora scrivere, quindi ho tolto quel permesso e ho controllato il risultato:

chmod o-w project_k.txt
ls -la

Cambiare i permessi di un file nascosto

Il team ha archiviato project_x.txt. Nessuno deve poterci scrivere, ma l'utente e il gruppo devono poterlo leggere. Il nome del file comincia con un punto, ed è per questo che è nascosto e compare solo con ls -a. Ho tolto la scrittura all'utente e al gruppo e ho dato la lettura al gruppo:

chmod u-w .project_x.txt
chmod g-w .project_x.txt
chmod g+r .project_x.txt
ls -la

Cambiare i permessi di una directory

Solo researcher2 può avere accesso alla directory drafts e a ciò che contiene. Per una directory, il permesso di esecuzione è quello che permette a un utente di entrarci. Il gruppo lo aveva ancora, quindi l'ho tolto. L'utente researcher2 aveva già l'esecuzione, quindi non c'era nulla da aggiungere:

chmod g-x drafts
ls -la

Riepilogo

Ho cambiato i permessi in modo che seguano le regole di accesso dell'organizzazione. Prima ho usato ls -la per vedere la situazione, ed è stato questo a dirmi quali modifiche servivano. Poi ho usato chmod tre volte, in modalità simbolica, su un file normale, su un file nascosto e su una directory, controllando ogni volta con ls -la.
